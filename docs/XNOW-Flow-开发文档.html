01

一句话说明

XNOW-Flow 是一个 TikTok iOS 云控系统：把自研的 xnower.dylib 注入 TikTok iOS 包（BH 版 43.7.0），让每台 iPhone 成为「云控设备」。网页后台通过 WebSocket/HTTP 下发指令，dylib 在手机端模拟真实用户操作（点赞/关注/评论/私信/养号/采集），并把结果回传。

端位置技术栈职责
iOS 注入层ios-plugin/xnow-dylib/Objective-C / dylib 注入跑在手机里：执行命令、模拟操作、抓包
后端backend/Python FastAPI / SQLAlchemy / SQLite下发命令、账号体系、任务调度、鉴权
网页后台login/ + backend/static/React 19 + Vite 8 / TS操作界面：设备控制、账号库、数据看板

构建链路：VPS 交叉编译 dylib → 注入 IPA → zsign 重签 → 装机验证。

三层网络拦截原理 本系统核心创新

TikTok 请求分两种路径，拦截必须分层：

   TikTok API 请求
     │
     ├─ 路径 A：系统 URL Loading System（NSURLSession）
     │    └→ XNOWURLProtocol 注册 → 能拿到 HTTP 明文
     │
     └─ 路径 B：Swift 自研网络栈（Pumbaa/PNSFoundation，字节自家）
          └→ TLS 层不透出明文（net_socket 实锤）
              └→ 退路：hook 请求模型 setter IMP → 构造请求瞬间
                 拿 URL / method / headers / body（net_request）
  • 第一层 ObjC swizzle（TikTokHooks.m）：替换 NSURLSession 相关方法 + 注册 NSURLProtocol。
  • 第二层 NSURLProtocol：XNOWURLProtocol（拦 TikTok API）+ XNURLProtocol（piggyback 通信）。
  • 第三层 fishhook（SocketHooks + fishhook.c）：重绑 socket 层 C 符号。
  • 第四层兜底（XNRequestHooks.m）：hook 请求模型 setter，构造瞬间拿明文。
网络安全铁律（v1.4.142 起） TikTok 私有类名禁止明文写进 dylib——明文会触发反 hook 检测 SIGTRAP 闪退（v1.4.141 闪退根因）。类名必须 XOR 运行时解码 + noinline + volatile 防 clang 常量折叠。新增 hook 代码同样处理。
已知问题：XNRequestHooks.m 潜伏构建炸弹 XNRequestHooks.m:13 的 #import "PnsRequestHooks.h" 是旧文件名（类已改名 XNRequestHooks），本地与 git 历史均无此文件，能编译过只因 VPS /root/xnow-build/ 残留 9 月 1 日同名旧文件兜底。清空 VPS 构建目录后下次构建立刻失败。应改为 #import "XNRequestHooks.h"（已登记 ISSUES 待修）。另外 SocketHooks.m / fishhook.c / fishhook.h 尚未 git 跟踪，改代码勿漏提交。

构建 → 注入 → 装机

① 编译 dylib build-vps-dylib-143c.py
本地源码 ios-plugin/xnow-dylib/
  → SFTP → VPS /root/xnow-build/
  → clang-16 交叉编译（arm64-apple-ios16.5 · -fobjc-arc · -Wno-everything）
      编所有 .m（除 MinimalTester）+ 所有 .c → 逐个 .o，任一 error 即停
  → ld64.lld 链接 → xnower.dylib
  → convert_cmds.py（私有命令转标准）
  → 下载回 build-artifacts-ci/xnower-143c/
两个坑 VPS 构建目录 /root/xnow-build/ 只 mkdir 不清理——残留旧文件会掩盖改名问题（见 §3 已知问题）。改文件后建议清目录重编一次。
Makefile 已过时（缺 SocketHooks/fishhook），不要用 Makefile。
② 注入 .tmp-inject-143c.py
xnower dylib → 上传 /root/xnow-build/
  → vps-inject.py 注入 LC_LOAD_DYLIB
      （VPS 无 43.7.0 原始包，以 static 最新已注入 IPA 连续注入）
  → zsign 重签（必须 -z 9！）→ 下载 TikTok_XNOW_v1.4.143c_BH.ipa
zsign 必须 -z 9 默认 zip_level=0 不压缩 → 包 374MB 膨胀 685MB → iPhone 8 Plus 装 74% 卡死。-z 9 回 ~391MB。修复版 zsign 在 C:\Users\Administrator\Downloads\zsign-src\bin\zsign（WSL 跑 Linux ELF）。
③ 装机
方式场景
爱思助手拖拽主力。pymobiledevice3 装 700MB+ 大包在 Windows 会卡死（installd 无活动）
爱思卡死杀 i4Tools/i4Service/i4ToolsService 重启（USB 不受影响）
装机验证一次装机验全批：按「装机验证清单」逐项下发实测，记 ✅真成功 / ❌假成功 / 🚨崩溃
发版门禁（攒批） 修复阶段不打包，攒够 ≥3 项「已修待验」 才编译打包；装机 = 全量验证（不许只验当前 bug）；发版前必跑 python regression-check.py all（open_tab / like / open_search / follow / go_home / backup 六条，三态验收），任一 🚨 或 ❌ 核心项 → 不发版先修。
